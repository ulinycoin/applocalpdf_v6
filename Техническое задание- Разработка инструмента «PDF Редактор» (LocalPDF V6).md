## 1. Контекст и Цель

### 1.1 Описание проекта
**LocalPDF V6** — локальная браузерная платформа для обработки PDF/Office-документов с плагинной архитектурой, воркер-исполнением и Studio-first UX.

### 1.2 Текущий статус инструмента
| Параметр | Значение |
|----------|----------|
| **Регистрация** | ✅ Зарегистрирован в реестре (`src/core/registry/register-tools.ts`) |
| **Роут** | ✅ Доступен по `/pdf-editor` |
| **Логика** | ❌ Отключена (заглушка в `logic/index.ts`) |
| **UI** | ⚠️ Частично готов (база в `StudioEditWorkspace.tsx`) |
| **Tier** | Pro |

### 1.3 Цель задачи
Активировать и доработать инструмент `pdf-editor` с акцентом на **простоту и удобство использования**. Пользователь должен иметь возможность открыть PDF, внести изменения и скачать результат без технических сложностей.

## 3. Требования к пользовательскому опыту (UX)

### 3.1 Принципы дизайна
> **Главный приоритет:** Интерфейс должен быть чистым, без визуального шума. Редактирование PDF часто перегружено сложными меню.

| Принцип | Реализация |
|---------|------------|
| **Контекстность** | Панель инструментов появляется только при выделении объекта |
| **Минимализм** | Скрытые технические детали, фокус на содержимом |
| **Отзывчивость** | Мгновенный отклик UI при вводе текста |
| **Безопасность** | Undo/Redo для любого действия, предупреждение при закрытии |

### 3.2 Пользовательские сценарии

#### Сценарий 1: Быстрое редактирование текста
```
1. Пользователь открывает PDF через /pdf-editor
2. Кликает на любой текстовый блок
3. Появляется курсор → пользователь редактирует текст
4. Панель форматирования (шрифт, размер, цвет) появляется автоматически
5. Пользователь кликает вне области → изменения сохраняются
```

#### Сценарий 2: Добавление аннотации
```
1. Пользователь выбирает инструмент "Заметка" из плавающей панели
2. Кликает на нужную область документа
3. Вводит текст заметки
4. Заметка сохраняется с визуальным маркером
```

#### Сценарий 3: Экспорт результата
```
1. Пользователь нажимает "Скачать PDF"
2. Запускается pipeline.worker.ts для сборки финального файла
3. Появляется индикатор прогресса
4. Файл загружается на устройство пользователя
```

### 3.3 Визуальные требования
| Элемент | Требование |
|---------|------------|
| **Панель инструментов** | Плавающая (floating), скрывается при бездействии |
| **Выделение объектов** | Подсветка при наведении (hover state) |
| **Границы страниц** | Видимые, но ненавязчивые |
| **Индикаторы** | Только при сохранении/экспорте (не при вводе текста) |
| **Адаптивность** | Компактный режим на экранах < 768px |

## 8. Риски и ограничения

### 8.1 Технические риски
| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| **Производительность на больших PDF** | Средняя | Высокое | Лимит страниц в `definition.ts`, прогресс-бар |
| **Потеря данных при закрытии** | Низкая | Критичное | Auto-save в VFS, warning before unload |
| **Зависимость от pdfjs-dist** | Низкая | Среднее | Shim-типы добавлены, тесты на импорты |
| **Конфликты версий браузеров** | Средняя | Среднее | E2E тесты в Chrome/Firefox/Safari |

### 8.2 Ограничения среды
- **Нет серверной обработки** — всё выполняется в браузере пользователя
- **Зависимость от памяти** — большие файлы могут требовать много RAM
- **QPDF не требуется** — редактор не использует `qpdf-engine.ts`
- **OCR не требуется** — редактор работает с существующим текстовым слоем
